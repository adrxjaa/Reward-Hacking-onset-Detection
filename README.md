# Detecting the Onset of Reward Hacking from RL Policy Behavior

A research framework for studying reward hacking (specification gaming) in reinforcement learning and detecting its onset from behavioural policy dynamics. The primary detector is trained and evaluated on a controlled RegionToggle task. The repository also contains discrete multi-environment experiments, a zero-shot generalisation study, an expanded feature experiment, and separate ADAS and continuous-car scenario demonstrations.

> **Scope note:** Results from different experiment folders use different datasets and protocols. Do not combine them into one aggregate score. In particular, the ADAS ablation CSV is generated by a synthetic feature/heuristic simulation and is not a measured learned-detector benchmark.

## Research overview

### Primary RegionToggle detector

The main pipeline contains two separate RL systems:

1. **Generator:** PPO trains a policy under clean, standard-exploit, and severe-exploit reward conditions (`w = 0.0`, `1.0`, and `5.0`). Checkpoints are saved during training.
2. **Detector:** A separate DQN agent observes a ten-dimensional behavioural vector and chooses `WAIT` or `FLAG`. The LSTM-DQN consumes a four-checkpoint window. The MLP-DQN is a non-recurrent comparison that uses the current checkpoint feature vector.

The canonical feature vector is:

1. `proxy_return`
2. `proxy_return_smoothed`
3. `proxy_return_trend`
4. `episode_length`
5. `action_distribution_change`
6. `state_visitation_entropy`
7. `state_visitation_change`
8. `path_efficiency`
9. `revisit_rate`
10. `behavioral_dispersion`

**Important feature caveat:** `revisit_rate` is computed from mean region-entry count divided by mean episode length. Region entries also participate in the task-onset criterion. The detector does not receive the onset label, true return, or goal-success field directly, but the feature is semantically coupled to one of the onset variables. `path_efficiency = 10 / episode_length` is also a deterministic transformation of episode length, not an independent trajectory measure.

### Main benchmark partitions

| Partition | Generator seeds | Runs | Use |
|---|---:|---:|---|
| Train | 42, 101 | 6 | Detector learning and normalizer fitting |
| Validation | 202 | 3 | Model selection |
| Unseen Phase 2 | 501–506 | 18 | Unseen-seed validation in RegionToggle |
| Final test | 701–706 | 18 | Held-out evaluation |

The 18-run Phase 2 and final-test partitions each contain six clean runs and twelve hacking runs. Each primary RegionToggle run has seven checkpoints (0 to 30,000 environment steps at 5,000-step intervals). The five detector seeds are repeated detector trainings on the same generator splits; they are not five independent generator datasets.

Metrics above are from the controlled ten-feature ablation, averaged across five detector seeds on the same 18 final-test generator runs. A premature flag before the labelled onset is treated as an incorrect alarm, not a true positive.

### Zero-shot generalisation study

The `generalisation_test/` study loads five original LSTM-DQN checkpoints trained on RegionToggle and evaluates them without fine-tuning on fixed run groups from CoinCollector, BatteryCollector, and VacuumCleaner.

| Environment | Evaluation runs | F1 (mean ± std across detector seeds) | Recall | Clean FPR | Mean delay |
|---|---:|---:|---:|---:|---:|
| RegionToggle reference group | 3 | 0.933 ± 0.133 | 0.900 | 0.000 | 0.50 |
| CoinCollector | 3 | 1.000 ± 0.000 | 1.000 | 0.000 | 1.00 |
| BatteryCollector | 3 | 0.800 ± 0.163 | 0.700 | 0.000 | 0.90 |
| VacuumCleaner | 3 | 1.000 ± 0.000 | 1.000 | 0.000 | 0.60 |

Exploit-mechanism results are F1 = 0.933 ± 0.133 for RegionToggle boundary oscillation, 0.880 ± 0.098 for resource respawn cycling, and 1.000 ± 0.000 for VacuumCleaner stationary farming.

**Cross-algorithm transfer is a failure case:** the reported PPO group scores 0.933 ± 0.133 F1, while the tested A2C and DQN groups both score 0.000 F1. The algorithm groups comprise eight episodes each and pair PPO control episodes with exploit episodes from the algorithm under test; they are not a fully matched factorial comparison. The generalisation run groups are small and use fixed generator seeds, so treat these results as exploratory rather than conclusive statistical evidence.

### Follow-on 16-feature detector

A separate follow-on dated 2 November 2026 adds six features to the canonical ten: `proxy_efficiency_divergence`, `entropy_trend`, `path_efficiency_trend`, `rolling_revisit_mean`, `rolling_entropy_std`, and `consecutive_anomalous_count`. It records 250 training episodes and five detector seeds. The five-seed summary does **not** show consistent improvement:

| Model | Features | Phase 2 F1 | Final-test F1 |
|---|---:|---:|---:|
| Original LSTM | 10 | 0.867 ± 0.067 | 0.967 ± 0.067 |
| Expanded LSTM | 16 | 0.817 ± 0.082 | 0.967 ± 0.067 |
| Original MLP | 10 | 0.950 ± 0.067 | 0.967 ± 0.067 |
| Expanded MLP | 16 | 0.733 ± 0.207 | 0.867 ± 0.194 |

These values belong to the separate `phase3_improved` rerun and should not be merged with the primary `phase3_final` results.

### Additional environments and prototypes

- **Multi-environment generator benchmark:** 15 recorded runs across RegionToggle, CoinCollector, and BatteryCollector, with PPO, A2C, and DQN generator policies. The report compares proxy reward, true reward, goal success, exploit events, and onset indicators. These are generator/onset experiments, not all learned-detector transfer evaluations.
- **VacuumCleaner:** 5×5 grid with a dock goal and respawning dirt; a policy can collect proxy reward by stationary cleaning/dumping behaviour.
- **Highway ADAS:** a three-lane ACC/AEB simulator with a near-miss crisis-save reward loophole. The stored rollout has 13 checkpoints, and the LSTM Q-values first favour `FLAG` at 20,000 steps in that scripted scenario. This is a single demonstration, not a multi-seed benchmark.
- **ADAS ablation caution:** `scripts/run_adas_feature_ablation.py` generates synthetic feature sequences and uses a heuristic stopping simulation; its CSV summary values are calibrated in the script. Do not quote these values as empirical learned-detector accuracy.
- **Continuous car:** PPO policies are trained in a 2-D kinematic-bicycle environment under a destination-progress reward and a speed-farming reward. The script compares trajectory geometry, but it loads the LSTM model without executing detector inference; it is an environment/trajectory demonstration, not a measured zero-shot detection result.
- **GridWorld and Battery Collector standalone baselines:** separate prototypes with their own training and logging procedures.

## Setup

Python 3.11+ is recommended. From the repository root:

```bash
python -m venv .venv
# Windows PowerShell:
.venv\Scripts\Activate.ps1
# macOS / Linux:
source .venv/bin/activate

pip install -r requirements-pinned.txt
```

## Running the project

Run the available test suite:

```bash
python -m pytest -q
```

Use the unified runner for the original project components:

```bash
python run_all.py --gridworld
python run_all.py --battery
python run_all.py --pilot
python run_all.py --onset
python run_all.py --detector
python run_all.py --all
```

Run the controlled ten-feature ablation with the settings recorded in its metadata:

```bash
python scripts/run_feature_ablation.py --seeds 0 1 2 3 4 --episodes 300
```

Run the separate zero-shot generalisation study:

```bash
python generalisation_test/scripts/run_generalisation_study.py
```

Other experiment scripts include:

```bash
python scripts/run_multi_env_experiments.py
python scripts/run_adas_feature_ablation.py
python scripts/train_and_plot_adas_onset.py
python scripts/run_car_experiment.py
```

These scripts write artifacts under `results/` or `generalisation_test/results/`. Check the experiment-specific source and metadata before comparing outputs; not all runners evaluate the same learned detector or use the same training protocol.

## Interpretation and limitations

- `revisit_rate` is derived from an event counter used in the onset definition; a trajectory-only revisit feature is needed to remove this coupling.
- The zero-shot environment groups contain few fixed runs and do not sample multiple generator seeds per environment.
- The current RegionToggle-trained detector fails on the tested A2C and DQN exploit-policy groups.
- The expanded 16-feature follow-on does not consistently outperform the original ten-feature detector.
- ADAS and continuous-car results are scenario demonstrations with limitations described above, not validated real-world safety claims.
- A zero false-positive rate on a small finite test partition is not a guarantee of zero false alarms in deployment.

## Citation and use

This repository is an experimental research framework. The reported environments and metrics are simulation results and should not be interpreted as evidence of deployment readiness in safety-critical systems. When reusing results, cite the exact experiment folder, its metadata, and the script that produced the result.
